# Maschinenlesbare Quelldatei des Golden-Inventars (DOC-ZAHLEN-DRIFT-82, Welle 3).
#
# Zweck: die R/C-Klassifikation der Goldens und ihre Zuordnung zu den
# Test-Targets waren handgepflegte Prosa-Zahlen in
# `feature/quality/golden-fixtures.md` (§4, R/C-Split) und
# `feature/quality/golden-references.md` (§7, Verteilung auf die Test-Targets).
# Eine Zahl in Prosa ist eine Kopie einer fremd gepflegten Tatsache und altert
# still. Diese Datei ist die Quelle; die Zahlen werden daraus ERZEUGT
# (`scripts/gen_doc_facts.sh`, Bloecke `golden-classes` und `golden-targets`)
# und per Drift-Gate (`scripts/check_doc_facts_drift.sh`) gegen die committeten
# Bloecke geprueft.
#
# Format:
#   * eine Kopfzeile mit den Spaltennamen: `golden|klasse|target`
#   * danach genau eine Zeile je committetem Golden, sortiert nach dem
#     Golden-Namen (LC_ALL=C, feste Byte-Reihenfolge) — die Sortierung ist Teil
#     des Vertrags: die Datei wird maschinell gelesen.
#   * `golden` = der Dateiname ohne Pfad. Die Goldens liegen in
#     `crates/lumina-gui/tests/snapshots/` (das Verzeichnis ist NICHT Teil
#     dieser Datei, damit die Zeilen unabhaengig vom Pfad bleiben).
#   * `klasse` = `R` (Render-Invariante) oder `C` (Chrome-/Layout-Invariante).
#   * `target` = der repo-relative Pfad des Test-Targets, das den Golden
#     erzeugt.
#
# Die Klassifikation ist eine MENSCHLICHE Entscheidung (GOLDEN-FIXT-31,
# `feature/quality/golden-fixtures.md` §2/§3): sie wird hier in ihre
# maschinenlesbare Form ueberfuehrt, nicht aus dem Bildinhalt abgeleitet. Der
# Generator rechnet aus dieser Datei, er entscheidet nichts.
#
# Aenderungen an dieser Datei sind ein sichtbares Ereignis: der Drift-Gate wird
# rot, bis die betroffenen Bloecke neu erzeugt sind. Zwei Zahlen muessen
# zueinander passen und werden vom Generator laut geprueft: die Zahl der Zeilen
# hier und `goldens.count` aus `scripts/golden_ref.lock` (die committete
# Baseline der Golden-Zahl; `scripts/golden_ref_test.sh` prueft dieses Lockfile
# gegen den Git-Index).
